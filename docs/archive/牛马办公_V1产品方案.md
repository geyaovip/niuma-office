## 1. 产品定位

牛马办公是一款面向中国用户的 **AI 桌面工作平台**。

产品目标不是做一个单纯的聊天机器人，而是让用户把真实工作交给 AI，由不同专家结合 Skill、MCP、知识库和本地电脑能力完成任务。

核心概念：

- **项目 Project**：围绕一个长期目标组织多个任务、项目资料与文件型产出的工作空间
- **任务 Task**：独立的 AI 工作执行单元；可以单独创建和运行，也可以归属于某个项目
- **专家 Expert**：谁来干
- **专家团 Expert Team**：谁和谁一起干
- **Skill**：怎么干
- **MCP / 连接器**：能连接什么
- **知识库 Knowledge**：长期参考什么资料
- **Memory**：AI 从长期交互中记住什么
- **自动化 Automation**：什么时候自动干
- **产物 Artifact**：任务最终生成的文档、表格、图片等结果

V1 采用 **Local-first + Lightweight Cloud**：

- AI Agent 与电脑操作主要在用户本机执行
- 云端负责账号、计费、模型网关、公共资源市场和运营管理
- 暂不建设 Cloud Agent Runtime

# 2. 产品整体架构

```text
                        牛马办公
                           │
        ┌──────────────────┴──────────────────┐
        │                                     │
   Desktop Client                        Cloud Platform
   用户工作端                            平台服务
        │                                     │
 Electron + React                    Cloud Backend
        │                                     │
 产品业务层                           Account / Billing
        │                            Model Gateway / Market
 OpenClaw Adapter                            │
        │                              PostgreSQL
 OpenClaw Runtime                            │
        │                              Admin Console
 Agent / Skill / MCP                   平台运营管理后台
 Browser / Computer
        │

```

### 技术基线

- Desktop：Electron
- UI：React + TypeScript
- 本地业务层：Node.js / TypeScript
- 本地数据库：SQLite
- Agent Runtime：OpenClaw
- Cloud Backend：Node.js + TypeScript
- 云端数据库：PostgreSQL
- Admin Console：React
- 模型调用：Model Gateway

V1 暂不引入 FastClaw。

## 4.3 项目

项目是用于组织长期工作的工作空间，但 **Task 是一级独立实体，Project 是可选容器**。

```text
Task
├── project_id = null
│   └── 独立任务
│
└── project_id = xxx
    └── 项目任务
```

用户可以：

- 直接点击「新任务」开始工作，不需要先创建项目
- 在项目内创建任务
- 将已有独立任务加入项目
- 将项目任务移出项目后继续作为独立任务使用

### 项目结构

```text
项目 Project
│
├── 项目说明 / Instructions
├── 项目资料
│   ├── 用户上传文件
│   └── 项目参考资料
│
├── 项目产出
│   ├── 文档
│   ├── 表格
│   ├── PPT
│   ├── 图片
│   ├── 代码
│   └── 其他生成文件
│
├── 默认专家 / 专家团
├── 默认 Skill / MCP
│
└── 关联任务（业务数据）
    ├── Task A
    ├── Task B
    └── Task C
```

### 项目文件与任务数据边界

项目的本地 Workspace **只保存项目资料和文件型产出**。

Task、Session、Message、Execution Log 不作为文件写入项目目录，而是作为独立业务数据保存在本地数据库，通过 `project_id / task_id` 与项目建立关联。

```text
Project Workspace（文件系统）
├── 项目资料
└── AI 生成文件 / 代码 / 文档等产出

SQLite（业务数据）
├── Project
├── Task
├── Session
├── Message
└── Execution Log
```

项目内 Task 生成的文件型产出默认写入该项目 Workspace，并记录来源 `task_id`。

独立 Task 生成的文件保存在该 Task 自己的 Workspace；若后续加入项目，可由用户选择是否将已有文件一并迁移到项目目录。

### 项目上下文

项目内任务可共享：

- 项目说明 / 长期指令
- 项目资料
- 项目级知识
- 默认专家 / 专家团
- 默认 Skill / MCP

但每个 Task 仍保持独立的会话与执行上下文，避免不同任务的聊天记录互相污染。

### V1 项目能力

- 创建 / 重命名 / 删除 / 归档
- 项目说明和长期指令
- 项目文件管理
- 项目产出汇总
- 在项目内创建多个任务
- 独立任务加入 / 移出项目
- 设置默认专家 / 专家团
- 设置默认 Skill / MCP
- 项目内任务搜索和状态查看

### 项目与知识库

项目资料不等于全局知识库。

项目中的资料默认只服务当前项目；用户可主动将高价值项目资料或 AI 产出加入独立知识库，供其他任务或项目长期复用。

### V1 暂不做

- 多人项目协作
- 项目成员 / 权限
- 项目看板
- 项目审批
- 云端项目文件同步

V1 首先把项目做好成个人用户的「长期 AI 工作空间」。

## 4.5 专家团

专家团由多个专家共同完成复杂任务。

```text
专家团
├── 团长
├── 成员专家
├── 协作规则
└── 输出规则
```

V1 支持：

- 团长统筹
- 任务自动拆解
- 顺序执行
- 并行执行
- 成员结果共享
- 团长汇总
- 最终统一交付

例如：

```text
新品上市专家团

营销负责人（团长）
├── 市场研究专家
├── 竞品分析专家
├── 内容运营专家
└── 视觉设计专家
```

专家团由平台管理后台组合，不依赖外部现成专家团资源。

## 4.6 自动化

自动化用于让 AI 持续工作。

V1 底层优先复用 OpenClaw 原生调度能力。

支持：

- 一次性定时
- 每天
- 每周
- 工作日
- 自定义周期
- 指定专家
- 指定专家团
- 执行完成通知
- 失败通知 / 简单重试

执行模型：

```text
Automation
    ↓
触发
    ↓
创建 Task
    ↓
专家 / 专家团执行
    ↓
结果进入任务中心
    ↓
桌面通知
```

V1 为本地执行，因此电脑关闭后任务无法继续运行。

## 4.7 技能

技能中心统一承载 AI 的扩展能力。

建议页面内部：

```text
技能

全部
Skill
连接器（MCP）
```

### Skill

表达“AI 怎么完成某类工作”。

来源包括：

- 官方 Skill
- OpenClaw 兼容 Skill
- ClawHub 等公开生态
- GitHub 合法来源
- 后续用户创建

外部 Skill 导入必须检查：

- Runtime 兼容性
- License
- 依赖
- 权限
- 安全风险

### MCP / 连接器

面向普通用户优先称为「连接器」。

例如：

- GitHub
- 飞书
- Gmail
- 数据库
- 搜索
- 企业系统

高级设置中再展示 MCP Server、参数等技术信息。

用户 Credential 优先保存在本机安全存储。

## 4.8 知识库

知识库是 AI 后续任务需要长期参考的资料集合。

支持：

- PDF
- Word
- Markdown
- TXT
- 网页
- 本地文件

支持：

- 创建多个知识库
- 上传 / 删除资料
- 查看解析状态
- 绑定专家
- 任务中主动引用

### 知识库、Memory 与任务产物必须分开

```text
任务产物
= AI 这次工作生成了什么

知识库
= 用户希望 AI 以后长期参考什么

Memory
= AI 从长期交互中记住什么
```

AI 生成的文档默认属于任务产物，不自动进入知识库。

任务完成后支持：

```text
生成报告
   ↓
任务产物
   ↓
[加入知识库]
   ↓
选择目标知识库
   ↓
解析 / 索引
```

系统可智能提示“建议加入知识库”，但 V1 不自动沉淀所有 AI 文档。

## 5.2 项目工作

```text
创建项目
   ↓
填写项目目标 / 指令
   ↓
添加项目资料
   ↓
```

```text

   ↓
```

# 10. 补充基础能力

除核心业务模块外，V1 需要补齐以下基础产品能力，避免客户端只有“功能页”而缺少完整使用体验。

## 10.1 全局搜索

统一搜索：

- 项目
- 任务
- 专家
- 专家团
- Skill
- MCP
- 知识库

V1 可先做关键词搜索，不建设复杂语义搜索系统。

## 10.2 通知中心

统一承载：

- 任务完成
- 任务失败
- 自动化执行结果
- 额度不足
- 客户端升级
- 系统公告

同时支持系统桌面通知。

## 10.3 权限与安全确认

对高风险操作提供确认机制，例如：

- 删除 / 覆盖文件
- 执行 Shell
- 操作浏览器账号
- 调用外部系统
- 发送消息 / 邮件
- MCP 高风险写操作

支持基础的「默认确认」和「本次任务授权」模式。

## 10.4 产物管理

产物是 AI 执行任务后生成的文件型成果，包括：

- 文档
- 表格
- PPT
- 图片
- HTML
- 代码 / 项目文件
- 其他生成文件

归属规则：

```text
独立 Task 产物
→ Task Workspace

项目内 Task 产物
→ Project Workspace
→ 同时记录 source_task_id
```

会话、执行日志不属于项目文件产物。

客户端需要提供统一的产物浏览体验，支持打开、定位本地文件、继续编辑、作为新任务输入或加入知识库。

## 10.5 模型与额度

客户端需要明确展示：

- 当前模型
- Auto 模型模式（后续可做智能路由）
- 剩余额度
- 本次任务消耗
- 自定义模型入口

# 15. Codex 开发原则

1. **先跑通闭环，再扩功能。**
2. **Local-first，V1 不建设 Cloud Runtime。**
3. **Task-first，不把产品做成 Chat-first。** Task 可独立运行，Project 只是可选的长期组织与上下文容器。
4. **OpenClaw 优先复用，不重复开发已有 Runtime 能力。**
5. **OpenClaw 必须通过 Adapter 接入。**
6. **产品 Schema 自有，避免锁死 Runtime。**
7. **专家、Skill、MCP 是平台内容资产，不等于 Runtime 配置文件。**
8. **项目文件、任务/会话数据、知识库、Memory 分离。** 项目目录只保存资料与文件型产出。
9. **平台模型 Key 永远不下发客户端。**
10. **用户 Credential 默认本地安全保存。**
11. **专家团使用统一编排引擎 + 模板配置，不为每个专家团开发独立逻辑。**
12. **管理后台与客户端同步设计，所有公共内容均应后台可配置。**
13. **UI 可参考 WorkBuddy 的信息架构和交互模式，但不直接复制其品牌资产和具体视觉实现。**

# 16. V1 最核心闭环

```text
注册 / 登录
      ↓
进入牛马办公
      ↓
┌──────────────────┬──────────────────┐
│                  │                  │
独立新建 Task      进入 / 创建 Project
│                  │
│                  └→ 在项目内新建 Task
│
└──────────────────┬──────────────────┘
                   ↓
          选择专家 / 专家团（可选）
                   ↓
             输入真实工作任务
                   ↓
       上传文件 / 引用知识库（可选）
                   ↓
               OpenClaw 执行
                   ↓
     Skill / MCP / Browser / Computer
                   ↓
             生成结果 / 文件
                   ↓
       独立 Task → Task Workspace
       项目 Task → Project Workspace
                   ↓
              保存任务历史
                   ↓
      高价值产出可加入知识库
                   ↓
       任务可进一步设置为自动化
```

V1 最重要的验收标准：

> **用户可以把一个真实工作任务交给“牛马”，牛马能够选择或调用合适的专家和能力，在本地完成任务，并交付可直接使用的工作结果。**
