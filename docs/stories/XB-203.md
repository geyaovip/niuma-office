# XB-203：Project、项目资料、项目 Task 和产物归属

- 状态：`done`
- 主文档：`docs/product/ui-and-flows.md` 第 7、11–12 节
- 关联决策：`D-008`、`D-018`

## 目标

让用户可以不依赖 Project 直接创建 Task，也可以把长期资料、任务和交付文件稳定归入一个 Project，并从项目页继续工作。

## 范围

- 必须实现：Project 列表、创建、现有文件夹可选绑定、重新授权、详情与空/错/恢复状态。
- 必须实现：项目资料、关联 Task、关联产物和项目内新任务入口；项目内 Task 默认继承 Project Workspace。
- 必须实现：历史任务与产物保留创建时的 Workspace 归属，修改默认根目录不静默迁移历史内容。
- 明确不做：多人协作、云端同步、Project 分享、完整文件编辑器和自动目录迁移。

## 契约变化

- Schema / API / Event：Project 增加持久化说明与资料关联；Task 与 Artifact 的 Project 归属必须可查询并保持稳定。
- Permission：绑定现有目录和重新授权使用系统文件夹选择器；Workspace 外文件仍不得作为项目产物登记。

## 验收

- 用户不创建 Project 也能正常完成独立 Task；创建 Project 不要求选择文件夹。
- 项目详情能看到真实资料、Task 和产物；空状态提供明确且可用的下一步。
- 从项目页新建 Task 自动带入该 Project；产物写入项目 Workspace 并只出现在正确项目中。
- 自定义项目目录失效时显示重新授权，不丢失历史记录，不伪造成功状态。
- 单元、持久化和真实 macOS 项目路径交互验证通过。

## 验证命令

- `npm run check`
- `npm run test:desktop`
- `./script/build_and_run.sh --verify`

## 完成记录

- Project 列表不再把默认工作空间伪装成项目；无项目时明确说明独立 Task 可直接使用。
- 新建 Project 默认在当前默认 Workspace 下创建带稳定 ID 的目录，选择现有文件夹与目录失效重新授权路径保持可用。
- 项目详情已实现正式的资料、关联 Task、交付产物与目录状态界面；项目资料经系统选择后复制到项目的“资料”目录并持久化来源。
- 项目 Task 自动携带项目资料路径作为只读上下文，产物写入对应 Project Workspace；独立 Task 仍使用默认工作空间。
- 从项目页新建 Task 会预选该 Project；从全局“新建任务”进入则恢复默认工作空间，不强制归入项目。
- `npm run check`、`npm run test:desktop` 通过，共 29 项桌面测试；`./script/build_and_run.sh --verify` 通过。
- 真实 macOS 客户端验证：项目空状态、默认目录创建、项目详情、项目内新任务预选和全局新任务恢复默认 Workspace 均符合预期。验收项目记录已移除，创建的测试目录移入废纸篓，可恢复。
