# XB-502：模型网关可靠性、用量与成本

- 状态：`in_progress`
- 主文档：`docs/architecture/technical-baseline.md` 第 7 节“模型网关”
- 关联决策：`D-006`、`D-007`、`D-028`

## 目标

让平台模型请求在上游限流、短时故障和路由异常时可控恢复，并留下可核对且不泄露用户内容的用量与成本记录。

## 范围

- 必须实现：请求 ID、候选路由、仅对明确可重试错误生效的有界重试/Fallback、跨进程熔断状态和安全错误归一化。
- 必须实现：按请求、设备、逻辑/物理路由记录输入、输出、缓存 Token、估算成本、上游请求 ID、状态和耗时；不得保存 Prompt、回复正文、平台 Key 或短时令牌。
- 明确不做：不接账号套餐、支付或余额扣减；不建设可视化用量后台；不承诺流式响应已经向客户端发送后还能无缝切换模型。

## 契约变化

- Schema：新增模型路由熔断状态与不可变用量账本。
- Gateway：请求先解析有序候选路由；只在尚未向客户端提交响应且错误属于超时、429 或 5xx 时尝试下一候选。
- API：客户端可传符合格式的请求 ID；响应和归一化错误返回同一 ID，不返回供应商内部配置。

## 验收

- 首选路由成功时只请求一次；429、明确的 5xx 或连接超时可切换到下一健康候选，400/401 等永久错误不得盲目重试。
- 连续故障会在 PostgreSQL 打开有限时长熔断，成功请求恢复状态；所有候选不可用时返回稳定、可恢复且不含供应商细节的错误。
- 成功与失败请求均写入去内容化账本；有 usage 时精确记账，无 usage 时明确标记未知而非伪造 Token 或成本。
- 单元、真实 PostgreSQL 集成、流式代理、生产真实路由和故障回归通过；静态回滚路径保持可用。
