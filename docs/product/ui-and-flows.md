# 牛马办公 UI 与核心流程基线

## 1. 参考边界

当前视觉与交互参考用户提供的 WorkBuddy v5.3.14 截图，包括整体布局、信息密度、任务输入、资源卡片、专家团执行和个人中心浮层。

允许参考：

- 左侧浅灰固定侧栏与主工作区
- 大留白、黑白灰主色、弱边框和低阴影
- 新任务的大输入框和能力快捷标签
- 专家、专家团、Skill、连接器的卡片网格
- 专家团成员状态 Chip、成员输出和团长汇总
- 侧栏底部账户入口及向上展开的个人中心浮层

不得复制：WorkBuddy 名称、Logo、猫形象、品牌插画、广告、积分、拉新、成长计划、专有文案和第三方资源图标资产。牛马使用自己的品牌、头像、图标库、文案与示例数据。

“参考 WorkBuddy”不等于使用 Demo 内容。客户端所有可见页面必须采用可正式交付的布局、真实状态和正式中文；测试数据只允许出现在开发 Fixture 与自动化测试中，不进入生产构建。

## 2. 设计与行业规范

牛马是 macOS 桌面应用，不以 iOS UI 规范作为主基线。规范优先级如下：

1. Apple `macOS Human Interface Guidelines`：窗口、侧栏、工具栏、菜单栏、键盘快捷键、深浅色、系统反馈和辅助功能。
2. 牛马产品设计 Token 与组件规范：保证 Electron/React 页面在所有模块一致。
3. WCAG 2.2 AA：对比度、缩放、焦点可见、错误提示、非颜色唯一表达和减少动态效果。
4. WAI-ARIA Authoring Practices：Dialog、Menu、Tabs、Listbox、Tree、Tooltip 等 Web 控件语义和键盘行为。
5. WorkBuddy 截图：只用于产品布局、信息密度和交互参考，不覆盖前述规范。

不照搬 iOS 的全屏导航、底部 Tab Bar、大触控尺寸和移动端手势。必须支持鼠标精确操作、完整键盘路径、窗口自由缩放、菜单栏命令、`⌘` 快捷键、Hover、Focus、右键菜单、系统深浅色和 Reduce Motion。

初始设计 Token：

- 字体：`-apple-system`，中文优先苹方，英文与数字跟随 SF 系统字体。
- 客户端使用灰阶工作台：主要按钮 `#202020`，选中背景 `#E3E3E3`；黄色只来自原创牛 Logo，必要状态色按语义使用。详细 Token 见 `brand.md`。
- 间距：4 / 8 / 12 / 16 / 24 / 32。
- 圆角：6（控件）、10（输入与卡片）、14（重要浮层）；避免全页面过度大圆角。
- 控件高度：28（紧凑）、32（标准）、36（主要操作）；长文本输入按内容扩展。
- 动效：状态反馈 120–200ms；尊重系统 Reduce Motion，任务执行不使用持续无意义动画。
- 窗口：定义最小可用尺寸并验证自由缩放、全屏、外接显示器与恢复上次尺寸。

## 3. 应用壳层

- 默认浅色；个人中心提供浅色/深色切换。
- 左侧栏固定，主区独立滚动；任务列表在侧栏内部连续滚动。
- 窗口变窄时先压缩主区边距和卡片列数，不隐藏核心入口。
- 所有图标来自统一图标库，不使用 Emoji 或手绘 SVG 代替产品图标。
- 不套用常见 AI 模板风格：紫蓝渐变、霓虹光晕、漂浮粒子、过量玻璃卡片、随机机器人插画和巨大空洞口号均不得作为默认视觉语言。
- 布局以真实内容、任务状态和操作层级为依据，不用装饰性卡片填满页面，也不为展示效果伪造模块。
- 正文强调可阅读性，运行日志使用更低视觉权重；普通用户不直接看到 OpenClaw 原始日志。
- 提供菜单栏命令和快捷键：新任务、搜索、显示/隐藏侧栏、停止任务、设置和帮助。
- 所有可交互控件必须有键盘焦点、可读名称和 VoiceOver 可理解的状态变化。

## 4. 新任务

主区中央显示：

- 牛马品牌问候语
- 办公、开发、设计等顶层场景切换
- 常用任务类型快捷标签
- 大尺寸多行输入框
- 添加文件、存储位置、权限模式、可选专家/专家团、模型和语音入口
- 提交按钮；运行中切换为停止按钮

存储位置默认显示“牛马默认位置”，不要求用户操作；点击后才提供选择现有文件夹或修改默认根目录。项目内新任务显示当前项目名称，不重复要求选择文件夹。

新任务默认不选择专家或专家团；只有用户从目录或输入框主动选择后才显示对应上下文。模型默认显示 `Auto`，平台供应商、Endpoint 和平台密钥不出现在普通用户界面。

最近任务直接显示在左侧，不为新任务页增加广告或营销 Banner。

## 5. 任务执行页

- 顶栏显示任务标题、搜索、分享、自动化和侧栏控制。
- 主内容按时间展示用户输入、执行计划、关键动作、等待确认、成员输出、最终结果和产物。
- 只展示对用户有帮助的过程摘要；底层思考内容、Prompt 和原始 Runtime 日志不得直接暴露。
- 专家团运行时，在输入框上方显示团长和固定成员 Chip：等待、运行、完成、失败、已停止。
- 点击成员 Chip 可定位或展开该成员的独立输出。
- 文件产物显示类型、名称、来源成员、打开、预览和 Finder 定位。
- 底部输入框用于补充信息、纠正方向和继续任务。

## 6. 专家·技能·连接器

一个一级入口，主区使用三个顶部 Tab：

```text
专家 | 技能 | 连接器
```

### 专家

- `专家 / 专家团` 二级切换
- 专家与专家团均由平台配置，不建设公开市场，不展示虚构作者、热度、销量或评分。
- 专家支持按名称、职责、简介、分类和标签搜索；无结果时给出可恢复的空状态。
- 专家卡片展示名称、职责、简介、分类和标签；详情展示稳定版本、工作规则、能力边界、实际权限和使用入口。
- 新任务默认不选择专家；选择单专家后只运行该专家，并在 Task、轮次和产物中保存专家身份与版本快照。
- 专家团卡片必须说明固定成员数量、成员职责和协作阶段

### 技能

- 精选技能、推荐、已安装、添加技能、搜索和分类
- 安装前展示权限、依赖、来源、License、版本和风险状态

### 连接器

- 平台连接器目录、已连接状态、权限范围和配置入口
- 飞书与 Telegram 的“接收任务渠道”在设置中单独管理，不与普通业务 MCP Credential 混用

## 7. 项目、自动化与知识库

- 项目页展示说明、资料、产物、默认专家/专家团、默认能力及关联 Task。
- 创建 Project 时直接使用牛马默认目录；“使用现有文件夹”作为可选操作。
- 自动化页展示下一次运行、最近结果、失败状态和电脑离线提示。
- 知识库页展示资料数量、解析状态、失败原因、绑定专家和引用入口。

## 8. 个人中心

账户入口固定在侧栏底部。点击后向上展开浮层，参考截图的分组与紧凑密度，但内部体验版只保留：

- 当前身份：本地体验用户；接入登录后显示邮箱。
- 平台模型用量与用户自定义模型入口；平台接入和用户自定义配置必须分开。
- 设置。
- 外观：浅色、深色、跟随系统。
- 消息渠道：飞书、Telegram 的连接状态与扫码入口。
- OpenClaw Runtime 状态以“本地执行服务”展示。
- 默认文件根目录、本地数据目录与存储占用。
- 帮助与反馈。
- 检查更新。
- 登录完成后增加退出登录。

当前不显示升级、积分余额、签到、邀请和成长计划。

## 9. 扫码绑定

### 通用流程

```text
个人中心 → 消息渠道 → 选择飞书/Telegram
→ 客户端向云端申请一次性 Pairing Session
→ 展示二维码、有效期和刷新按钮
→ 手机扫码并在目标应用完成授权/启动机器人
→ 云端验证渠道身份与 Pairing Token
→ 绑定到当前 device_installation_id
→ Mac 实时收到绑定成功事件
→ 发送一条测试消息
→ 显示“已连接”及解绑入口
```

二维码 5 分钟失效、仅可使用一次；用户取消、刷新、绑定成功或连续失败后立即作废。二维码不包含平台密钥。

### Telegram

- 二维码使用官方 Bot 深链：`https://t.me/<niuma_bot>?start=<pair_token>`。
- 用户点击 Start 后，云端从 Telegram Update 获得用户和 Chat 身份，并消费一次性 Token。
- 群聊绑定使用 `startgroup` 或在群内 `@牛马 /bind <short_code>`；绑定者必须拥有相应群管理权限。

### 飞书

- 二维码打开牛马飞书应用授权页，`state` 对应一次性 Pairing Session。
- 云端使用授权回调取得用户 `open_id`，再绑定牛马飞书机器人私聊。
- 群聊由管理员将牛马机器人加入群，随后在群中 `@牛马 绑定` 完成确认。
- 用户不接触 App ID、App Secret、Webhook 或 OpenClaw 配置。

## 10. 渠道任务流程

- 私聊中的普通消息默认创建或继续该私聊当前 Task；显式“新任务”创建新 Task。
- 群聊只有 `@牛马` 才触发；每个群/话题保持独立上下文。
- 渠道内显示已接收、排队、等待 Mac、执行中、等待用户、完成和失败状态。
- 需要本机高风险确认时，渠道只提示“请在 Mac 上确认”，不得在群聊直接批准。
- Mac 离线时云端排队最多 24 小时；上线后按创建时间领取。过期任务不执行，并向原渠道说明。
- 最终消息优先返回摘要和产物链接/附件；完整过程保留在 Mac 客户端。

## 11. 必备界面状态

每个主要页面和动作必须设计：加载、空、离线、无权限、额度不足、解析中、失败、部分成功、取消、重试和恢复状态。渠道绑定另需二维码过期、扫码未确认、身份已绑定其他设备、Bot 被移除和权限被撤销状态。

## 12. 正式文案标准

- 先写用户能完成的事情，再说明实现方式；不使用“赋能、颠覆、无限可能、重新定义、一键开启”等空泛套话。
- 按钮使用明确动作，如“下载 macOS 版”“选择文件夹”“重新连接”，不使用“立即体验”“探索更多”等含义不明的操作词。
- 状态文案必须说明发生了什么、用户是否需要操作、下一步是什么；不得直接展示异常堆栈、供应商错误或 OpenClaw 术语。
- 不虚构客户名称、使用量、成功率、媒体评价、合作伙伴、价格和产品能力。
- 中文名称、标点、大小写、时间、文件大小和模型名称遵循统一词表；同一对象不得在不同页面混用多个叫法。
- 发布前逐页检查标题、按钮、空状态、错误、确认框、通知、帮助链接和法律文字；任何占位符、Lorem、测试账号、无效链接均阻塞发布。
- 客户界面必须同时通过内容审校和视觉审校：术语一致、信息层级明确、对齐与间距稳定、主要操作真实可用；“看起来完整”不能替代实际闭环。
