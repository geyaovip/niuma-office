# 牛马办公正式官网基线

官网主标题必须围绕正式 Slogan“专门替‘牛马’干活的 AI 办公工具”展开，不能改写成泛化的 AI 助手套话。

官网是唯一公开 Web 产品面。首版不建设、发布或宣传 Web 版任务工作台；所有任务执行、项目、专家团、Skill、连接器、知识库和自动化功能均在 macOS 客户端完成。Electron Renderer 在浏览器中打开仅用于本地开发预览和设计验收，不属于交付路由。

## 1. 目标与参考边界

官网是正式客户交付的一部分，不是宣传 Demo。它必须让访客在不安装客户端前准确回答：牛马是什么、适合完成什么工作、数据在哪里执行、支持哪些系统和渠道、如何下载、遇到问题去哪里。

正式主站使用 `https://alipayclaw.cn/`，所有可索引页面以根域名作为唯一 Canonical；`www.alipayclaw.cn` 只允许永久跳转到根域名。消息与设备 API 使用 `https://api.alipayclaw.cn/`，安装包和版本清单使用 `https://download.alipayclaw.cn/`，三个载体不得混用 Cookie、可写目录或缓存策略。

信息叙事可参考 [WorkBuddy 官网](https://www.workbuddy.cn/) 当前公开首页的顺序：导航、首屏价值、产品演示、场景能力、生态连接、方案信息、下载行动和服务页脚。不得复制其品牌、视觉资产、专有文案、腾讯生态、价格、积分、活动、客户背书或在线使用入口。

## 2. 第一版路由

| 路由 | 用途 |
|---|---|
| `/` | 首页：产品定位、核心闭环、主要场景、本地执行、专家团和下载行动 |
| `/download` | macOS 下载、当前版本、发布日期、系统要求、Apple Silicon/Intel 状态、文件大小与校验信息 |
| `/guide` | 安装、首次任务、Workspace、权限、专家团、渠道绑定和常见问题 |
| `/security` | 本地/云端数据边界、权限确认、Keychain、自定义 API Key 与消息中继说明 |
| `/privacy` | 经确认的隐私政策 |
| `/terms` | 经确认的用户协议 |
| `/feedback` | 正式反馈方式、需要提供的信息与隐私提醒 |
| `/releases` | 版本更新记录、已知问题和最低系统版本 |

没有正式内容时，法律、价格和联系方式页面不得用生成文案顶替上线。首版不提供 `/pricing` 或 Web 在线使用入口；该边界是当前正式产品决策，不把 Web 工作台作为待上线占位能力。

## 3. 首页结构

1. 顶部导航：产品能力、使用场景、安全、使用指南、下载。
2. 首屏：一句明确定位、一段结果描述、主按钮“下载 macOS 版”、次按钮“查看使用指南”。
3. 真实产品界面：使用经过脱敏的正式客户端截图或短演示，展示从任务到文件交付的完整闭环。
4. 主要场景：文档处理、研究分析、数据整理、演示文稿、内容生产、开发协作；只展示已通过验收的能力。
5. 固定专家团：说明成员分工、过程可见和团长汇总，不虚构临时专家。
6. 本地执行与数据边界：说明任务在 Mac 执行、云端承担哪些必要能力，以及高风险操作如何确认。
7. 系统要求与下载：版本、兼容性、当前签名/公证状态、SHA-256、内部体验包安装步骤和更新方式。
8. 帮助与法律页脚：指南、反馈、隐私、协议、版本记录、运营主体和依法需要的信息。

飞书、Telegram 与邮箱登录在完成正式验收前不出现在公开首页、指南或结构化数据中；能力通过验收后再同步增加对应页面内容。

## 4. 视觉与内容原则

- 与客户端共用 `brand.md` 定义的原创牛 Logo、石墨黑字标、暖黄色品牌点缀、字体、图标和截图规范，但官网采用适合网页阅读的响应式版式。
- 参考产品叙事和信息密度，不复刻 WorkBuddy 的画面、动画、卡片组合或品牌识别。
- 首屏避免巨大空洞口号；主标题必须能独立说明产品类型或核心结果。
- 不使用 Emoji、AI 生成感插画、无意义渐变光效、悬浮粒子和大量玻璃卡片制造“科技感”。
- 场景示例使用真实任务和真实产物，敏感内容必须脱敏；不得出现 Lorem、占位图、Mock 数据标记或无法点击的按钮。
- 不使用“赋能、颠覆、重新定义、无限可能、一键开启”等泛化营销词，不编造客户数、节省时间、成功率和媒体评价。
- 所有公开声明必须与当前正式版本一致；能力下线或限制变化时同步更新官网。

## 5. 首版 SEO 基线

SEO 是官网信息架构和工程实现的一部分，不是上线后的独立优化项目。

### 渲染、路由与索引

- 首页、下载、指南、安全、版本记录等公开页面使用静态生成或服务端预渲染；关键正文、标题和链接必须出现在初始 HTML 中，不交付只有 App Shell 的纯客户端渲染页面。
- 每项内容只有一个稳定、可读、可抓取的正式 URL；不使用 `#/` 路由、随机 ID 或同内容多地址。改址使用服务端永久重定向。
- 正确返回 `200`、`301/308`、`404` 等状态；不存在的页面不得返回带错误文案的 `200` 形成 Soft 404。
- Production 允许索引；Preview、测试、管理后台、临时下载和带敏感参数的页面统一 `noindex`。不得仅依赖 `robots.txt` 隐藏敏感内容。
- `robots.txt` 明确生产抓取范围并声明 `sitemap.xml`；站点地图只包含 Canonical、可索引且返回 `200` 的正式页面，并提供准确 `lastmod`。

### 页面级语义

- 每页具有唯一且自然的 `<title>`、Meta Description、Canonical、单一主 `h1`、层级连续的标题和可读 URL。
- `<title>`、`h1`、首段和正文主题一致；不堆砌关键词，不为了搜索引擎复制近义段落或牺牲正式中文。
- 内部导航使用真实 `<a href>` 和描述性锚文本；重要页面从首页或上级页面可到达，不依赖按钮点击或 JavaScript 事件才暴露链接。
- 图片使用有意义的文件名、准确 `alt`、固定宽高和响应式资源；装饰图使用空 `alt`，产品截图说明真实页面与任务场景。
- 每页同步提供 Open Graph 与分享卡片信息；分享标题和描述不得与搜索元数据表达冲突。

### 内容与结构化数据

- 内容围绕真实用户问题组织：产品是什么、macOS 如何使用、能完成哪些办公任务、文件在哪里、权限如何控制；尚未验收的渠道能力不用于公开 SEO 内容。
- 首页与功能页形成清晰内部链接；指南页面回答具体问题，避免把所有关键词堆在首页。
- JSON-LD 只标注页面可见且真实的信息。基础类型使用 `Organization`、`WebSite`、`BreadcrumbList`；`SoftwareApplication` 仅在名称、操作系统、版本、下载和价格/Offer 等必需事实完整时启用，不编造字段换取富摘要。
- 法律、帮助、安全和版本内容由对应负责人审核；自动生成内容必须人工审校，不批量生产低价值 SEO 页面。

### 搜索平台与持续验证

- 上线时同时完成 Google Search Console 和百度搜索资源平台的域名验证、站点地图提交、首页及核心页面 URL 检查。
- 发布检查包含抓取后的 HTML、Canonical、索引指令、结构化数据、移动端渲染、404、重定向链和站内死链。
- 上线后使用搜索平台观察索引、抓取异常、关键词与点击，但首版必须具备完整技术基线；后续工作是依据真实数据改善内容，不是补做缺失的 SEO 工程。

## 6. 工程与上线要求

- 响应式支持桌面、平板和手机；键盘可用，符合 WCAG 2.2 AA，并尊重 Reduce Motion。
- 图片按尺寸输出现代格式并保留清晰度；首屏避免不必要脚本。Core Web Vitals 在移动端和桌面端第 75 百分位目标为：LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1。
- Preview 与 Production 分离；所有链接、下载、表单和法律页在生产域名逐一验证。
- 下载地址来自共享云服务器独立发布目录中的受控版本清单；展示版本、签名、公证、SHA-256 和系统要求，失效时给出明确状态而不是假成功。
- 内部体验阶段必须明确显示“未签名内部体验包”，说明 macOS 可能提示无法验证开发者，并提供通过 Finder 右键“打开”完成首次启动的系统标准路径；不得引导用户关闭 Gatekeeper 或修改全局安全设置。
- 反馈提交、统计和错误采集遵循最小化原则；启用任何第三方统计前先完成隐私评估和必要告知。

## 7. 验收

- 新访客可以在首页理解产品定位、主要能力、本地执行边界和下一步操作。
- 首页展示的每项能力都有当前客户端真实实现和可复现路径。
- macOS 下载可用，版本、SHA-256 与文件信息准确；内部体验包的未签名状态和首次打开步骤准确，正式公开包上线前再把签名和公证验证设为发布门禁。
- 指南、安全、隐私、协议、反馈、版本记录和 404 均可访问，不存在占位内容或死链。
- 桌面与移动端完成真实浏览、键盘、VoiceOver/语义和性能验证；抓取到的初始 HTML 包含主要内容和链接。
- 每条公开路由的标题、描述、Canonical、索引指令、Open Graph、状态码和结构化数据通过自动检查；`sitemap.xml` 与实际 Canonical 页面一致。
- Google Search Console、百度搜索资源平台完成站点验证和站点地图提交，核心 URL 没有阻塞抓取或明显渲染错误。
- 发布前由人工逐字检查所有标题、正文、按钮、提示、页脚和元数据，确认表达自然、准确、克制且无开发术语。
